# 칸 명세표

앱이 말하는 모든 칸의 기준표다. 코드를 만들거나 고칠 때 먼저 이 표를 본다.
표를 바꿔야 하면 **사용자와 상의한 뒤** 고친다. 표와 코드가 다르면 표가 기준이다.

기준 시점: 2026-10-02, versionCode 179.

## 원칙 (모든 칸 공통)

1. **지어내지 않는다.** 원본에 있는 값만 말한다. 시계 → 남은 분 변환은 허용.
2. **칸끼리 건드리지 않는다.** 한 칸을 고치려고 다른 칸 파일을 열지 않는다. 상태 공유·호출 금지. 현재 교통 정보는 읽기만 한다.
3. **모르면 조용히 넘어가지 말고 안내한다.** 사용자가 행동을 정하는 정보(환승 시각 등)를 못 읽으면 "휴대폰 화면에서 확인해 주세요"로 알린다.
4. **브리핑은 여정당 한 번.**

## 공통 통로

| 이름 | 하는 일 |
|---|---|
| `SpeechMouth` | 방금(30초 안) 말한 것과 같은 종류(도보/버스 번호/지하철 노선)·같은 대상이면 삼킨다. 직전 한 줄과만 비교. 지하철은 칸(10·5·2·곧)이 다르면 같은 노선이어도 삼키지 않는다 |
| `SpeechSink` | 한국어 TTS. 판단하지 않음 |

## 알려진 빈칸 (상의 전 손대지 않음)

- 구글이 대기 단계 없이 바로 탑승으로 넘어가면 환승 버스 카운트다운이 없다.
- 네이버 첫 ETA가 5분 이하이면 10분 칸은 원래 없다(원본이 건너뜀).
- "승차역 부근"은 9/18 기준 실측 0건이었다. 지금은 이 신호로 말하는 칸이 있다 → 실측 확인 필요.
- `SpeechMouth`는 문장 글자로 판단한다(종류·키로 넘기는 구조 아님).
- 네이버 시작 브리핑이 화면에 분이 없으면 302 시각을 기다리다 "승차역 부근" 때 늦게 나와 네이버 음성과 겹칠 수 있다. 직후 지하철 대기 멘트가 같은 내용을 한 번 더 말할 수 있다.
