# 교통음성알림 헌법 V2

적용 범위: **Naver 교통음성알림**. Google · TMAP · Memory Engine은 이 헌법의 대상이 아니다.
확정일: 2026-09-18 · 상태: V2 (개정은 제15원칙에 따른다)

**V1과의 관계.** V1(2026-09-12)을 폐기하지 않는다. V1 제1~15원칙과 제2~5장을 그대로 계승하고,
V2는 그 위에 **제16~22원칙 · 제6장(기본 정책 계약) · 제7장(사용자 Override) · 제8장(기능 등급) ·
제9장(검증)** 을 추가한다. V1 본문은 계속 유효하며, V1 부록 중 실측과 충돌한 항목만 개정했다(부록 H).
운영 문서는 V2다. V1은 제1~15원칙의 원문 출처로 남는다.

이 문서는 개발 설명서가 아니다. **무엇을 해도 되고 무엇을 하면 안 되는지를 판단하는 기준점**이다.
구현 방법 · 숫자 · 문자열 · 클래스 이름은 본문에 두지 않는다.

## 제1장. 핵심 원칙

### 제1~15원칙 — V1 계승

V1 제1장의 15원칙을 원문 그대로 유지한다. 두 곳만 승격한다.

- **제5원칙에 추가** — 모든 침묵에는 **상한과 구분 가능한 이유**가 있다. (V1 4-4를 원칙으로 승격)
- **제7원칙에 추가** — 상태 초기화는 **소유자가 스스로** 한다. 호출자가 리셋 목록을 기억해야 하는
  구조를 만들지 않는다. (V1 3-1을 원칙으로 승격)

### 제16원칙 — 입력은 계약이 아니라 관측이다
외부 앱이 주는 것은 우리가 통제할 수 없는 사실이다. 우리 정책이 기대하는 값이 오지 않는 것은
**위반이 아니라 정상 상황**이다. 기대값을 근거로 입력을 보정하거나 보간하지 않는다.

### 제17원칙 — 없는 데이터를 만들어 말하지 않는다
관측되지 않은 교통 사실(ETA · 차량 · 행선 · 칸 번호)을 계산 · 추정 · 기본값으로 채워
사용자에게 **실제 교통상황인 것처럼 말하지 않는다.**
단위 변환과 형식 정규화(시계 → 남은 분)는 허용한다. **생성은 금지한다.**

### 제18원칙 — 원본과 추론은 이름이 달라야 한다
원본에서 직접 온 값과 우리가 만든 값은 타입 · 필드명 · 로그에서 구분된다.
문서는 추론을 원본처럼 서술하지 않는다.
(차량 identity · 현재/다음 차량 · 단계는 모두 **추론**이다. 부록 G-4 참조.)

### 제19원칙 — 하나의 규칙에는 하나의 정의
같은 판정 규칙(단계 사다리 · 동일 차량 판정 · 즉시 도착 판정)의 구현은 **한 곳에만** 존재한다.
다른 계층이 필요하면 **호출**한다. 복제하지 않는다.

### 제20원칙 — 기본 계약은 기능 변경으로 흔들리지 않는다
제6장의 기본 정책 계약은 새 기능 · 수정 · 리팩터링의 **부수효과로 바뀌지 않는다.**
바꾸려면 해당 하위 헌법을 **먼저** 개정하고 보호 테스트를 함께 고친다.
코드를 먼저 고치는 것은 위반이다.

### 제21원칙 — 기능에는 등급이 있다
모든 기능은 `확정 · 정책 · 실험 · 관측` 중 하나다.
**낮은 등급이 높은 등급의 상태를 변경 · 소모 · 초기화할 수 없다.**
등급은 코드가 아니라 문서가 정한다(부록 E).

### 제22원칙 — 미검증 신호를 게이트로 쓰지 않는다
실측에서 확인되지 않은 신호를 다른 기능의 발화 조건으로 삼지 않는다.
필요하면 그 기능을 `관측` 등급에 두고, **기본 경로는 그 신호 없이 완결되어야 한다.**

## 제6장. 기본 정책 계약 (신설)

### 6-1. 정의
기본 정책 계약은 **사용자 설정이 없을 때 항상 적용되는 우리의 음성 약속**이다.
외부 데이터 계약이 아니다. **외부 데이터가 이 계약을 만족시킬 의무는 없다.**

### 6-2. 대기 안내 사다리 — 모양 (불변)
- 대상은 **추적 중인 한 대의 차량**이며, 기준은 **도착까지 남은 분**이다.
  알림 문구 · chip · 표시 형식이 아니다.
- 칸은 **내림차순으로만** 진행한다.
- 한 차량에 대해 각 칸은 **최대 1회** 발화된다.
- 낮은 칸을 발화하면 남은 상위 칸은 **소모된다.**
- 가장 낮은 칸(즉시 도착)은 **간격 규칙에서 면제**된다.
- 칸 집합은 **추적 차량이 바뀔 때만** 초기화된다.
  다른 어떤 기능 · 화면 · live 신호도 칸 집합을 초기화하지 않는다.

### 6-3. 데이터 게이팅 (불변)
칸은 **관측된 원본 ETA가 그 칸에 도달했을 때만** 발화된다.
원본이 어떤 칸을 건너뛰면 그 칸은 **발화 없이 소모된다.**
건너뛴 칸의 부재는 결함이 아니며, 이유로 기록된다(제17원칙).

> 실측 근거: 원본이 시계에서 곧바로 2분으로 바뀌어 10 · 5가 존재하지 않은 주행,
> 첫 관측이 이미 1분이었던 주행이 모두 확인되었다(부록 G-2).

### 6-4. 소유권 (불변)
각 수단의 대기 판정(pin · 추적 · 칸)에는 **단일 소유자**가 있다. 다른 계층은 **결과만** 받는다.
**사다리 판정 함수는 프로젝트에 하나만 존재한다**(제19원칙).

### 6-5. 침묵의 설명 (불변)
칸을 말하지 않은 모든 경우는 다음이 **구분 가능**해야 한다.

pin 없음 · 후보 없음 · 부분 관측 유지 · 출처 불일치 유지 · 간격 · 이미 소모 · 칸 아님 ·
**원본 미도달** · 사용자 비활성

> `원본 미도달`이 다른 항목과 구분되어야, "10분을 말하지 않았다"가
> **정상(원본 없음)** 인지 **결함(있었는데 침묵)** 인지 로그로 종결된다.

### 6-6. 구체 값의 위치
칸의 숫자와 시간 값은 **각 수단의 하위 헌법**에 둔다. 본문은 **의미와 모양만** 규정한다.
값은 V1 부록 B(Parameter)에 두지 않는다 — 기본 계약은 자유 변경 대상이 아니다.

- 버스: `docs/BUS_WAIT_CONSTITUTION.md` 의 「기본 계약」 절

## 제7장. 사용자 Override (신설)

- **7-1.** 사용자 설정은 헌법을 개정하지 않는다. **헌법이 명시한 범위 안에서 기본 정책 값을 대체한다.**
- **7-2. 허용:** 각 칸의 활성/비활성, 칸의 분 값, 간격 값, 문구 선택.
- **7-3. 금지:** 칸 순서 역전 · **원본에 없는 칸의 강제 발화**(제17원칙) · 소유권과 계층 경계 변경 ·
  침묵 이유 기록 비활성 · 즉시 도착 칸의 면제 규칙 제거.
- **7-4. 부재와 오류:** 설정이 없거나 해석에 실패하거나 허용 범위를 벗어나면
  **기본값을 사용하고 그 사실을 기록한다.** 침묵으로 처리하지 않는다.
- **7-5. 해석 지점 단일화:** 설정 → 유효 정책 변환은 **한 곳**에서만 일어난다.
  Judge와 Speech는 설정을 직접 읽지 않는다.
- **7-6. 적용 시점:** 유효 정책은 **Journey 시작 시 한 번 확정**되고 주행 중 바뀌지 않는다.
  (주행 중 사다리가 변하면 제1원칙이 깨진다.)
- **7-7. 전부 비활성:** 모든 칸을 끈 것은 **유효한 사용자 의사**다. 그때의 침묵은 결함이 아니며,
  이유로 기록된다.

## 제8장. 기능 등급 (신설)

### 8-1. 등급 정의

| 등급 | 뜻 | 보호 |
| --- | --- | --- |
| 확정 | 실측으로 검증되고 보호 테스트가 있다 | 헌법이 직접 보호한다 |
| 정책 | 동작하지만 문구 · 조건이 조정될 수 있다 | 하위 문서가 관리한다 |
| 실험 | 제품 판단이 진행 중이다 | 언제든 되돌릴 수 있어야 한다 |
| 관측 | 신호가 아직 검증되지 않았다 | 로그만 남긴다. **발화하지 않는다** |

### 8-2. 등급 간 규칙
- 낮은 등급은 높은 등급의 상태를 **변경 · 소모 · 초기화할 수 없다.**
- **실험은 자신의 상태만 갖는다.** 확정 기능의 중복 방지 칸을 빌리지 않는다.
- **관측 등급의 신호는 어떤 기능의 발화 조건도 될 수 없다**(제22원칙).
- 등급 승격은 **실측 근거와 보호 테스트 추가를 함께** 요구한다.

### 8-3. 구현 중립성
헌법은 특정 클래스 · 파일 · 판단 엔진 이름에 의존하지 않는다.
판단 엔진은 교체될 수 있고, **교체 후에도 제6장은 그대로 성립해야 한다.**
**두 개의 판단 엔진이 동시에 발화하지 않는다.**

## 제9장. 검증 (신설)

- **9-1.** 제6장을 대표하는 테스트 세트를 **보호 테스트**로 지정한다. 목록은 부록 F에 둔다.
- **9-2.** 보호 테스트가 빨간 변경은 **그 자체로 헌법 위반**이다.
  테스트를 고쳐 초록으로 만드는 것으로 해결하지 않는다.
- **9-3.** 보호 테스트를 수정하는 커밋은 **하위 헌법 개정을 포함**한다.
- **9-4. 순서:** `헌법 → 계약 테스트 → 구현 → 실기기`. 역방향으로 진행하지 않는다.

```
기능 A 수정 → 보호 테스트 실행 → 실패
   → 기능 A 변경이 헌법 위반이다 (원인을 제거한다)
   → 또는 하위 헌법 개정이 먼저 필요하다는 신호다
```

# 부록 A — Policy (변경 가능, 헌법 아님)

V1 부록 A를 계승한다. 이번 개정 사항은 다음과 같다.

- **A-1** 버스 대기 안내 정책 — `docs/BUS_WAIT_CONSTITUTION.md`. 변경 없음(그 문서 자체는 개정됨).
- **A-2** 출처 정책 — 알림 ETA 주 입력, 화면 시트 보조. **V1의 "구현에 반영되어 있지 않다" 주석은 삭제한다.**
  화면 꺼짐 시 시트 소유권 해제는 구현되어 있다.
- **A-3** 침묵 정책 — 관측 유예에는 상한이 있다(구현됨). **V1의 "현재 상한이 없다" 주석은 갱신한다.**
  상한이 없는 침묵은 관측 등급 신호를 기다리는 대기와, 소모된 칸이다.
- **A-4** 지하철 · 환승 · 하차 정책 — **개정.** 칸 안내(빠른 하차 · 빠른 환승)의 발화 조건에서
  **미검증 신호 의존을 제거한다**(제22원칙). 빠른 하차 정보는 첫 승차 알림 본문에 이미 포함된다(부록 G-6).
- **A-5** 첫 안내 브리핑 정책 — 변경 없음. **브리핑은 칸을 소모하거나 초기화하지 않는다**(6-2).

# 부록 B — Parameter (변경 가능, 헌법 아님)

V1 부록 B를 계승한다. **단, 「단계 = 10 / 5 / 2 / 곧」 행은 부록 B에서 삭제하고
버스 하위 헌법의 「기본 계약」 절로 이전했다.** 기본 계약은 자유 변경 대상이 아니다(6-6, 제20원칙).

그 외 값(간격 초 · 유예 초 · 허용 오차 · 문턱 · 채널 ID · 정규식 · 클래스명 · 로그 태그)은
V1 부록 B와 동일하게 다룬다. **값으로 헌법을 우회하지 않는다.**

# 부록 C — 개발 및 테스트 절차

V1 부록 C를 계승한다. 두 항목을 추가한다.

**C-7.** 새 기능 작업 중에는 **확정 등급 기능의 파일을 열지 않는다.**
열어야 한다면 그것은 하위 헌법 개정 작업이며, 별도 커밋이다.
**C-8.** 상태 초기화 호출을 한 줄 더 추가하는 변경은 **설계 실패 신호**다(제7원칙).
소유자가 스스로 초기화하도록 옮긴다.

# 부록 D — 구현 매핑

V1 부록 D를 계승한다. **개정 없이 갱신한다.** D-3의 원칙별 준수 상태는 갱신 시점의 사실로 다시 쓴다.

# 부록 G — 실측 근거 (2026-09-15 ~ 2026-09-18)

이 조항들이 왜 존재하는지의 사실 근거다. **해석이 아니라 관측이다.**
출처: 기기 observe JSONL 22개 파일(302 알림 · 접근성 이벤트 · 접근성 트리).

- **G-1.** 302 알림은 title 기반 스트림이고 고유 title 163종이 관측되었다.
- **G-2.** 원본은 ETA만 준다. **단계(10 · 5 · 2)를 보내지 않는다.**
  지하철 ETA는 **시계(HH:mm)** 와 **상대(N분)** 두 계열이며 한 대기 중에 번갈아 나온다.
  시계에서 곧바로 2분으로 바뀌어 **10 · 5가 존재하지 않은 주행**, 첫 관측이 **이미 1분**이었던 주행이
  모두 확인되었다. → 6-3의 직접 근거.
- **G-3.** 버스 ETA는 `노선 (N분)` · `(곧 도착)` 문자열이며 한 알림에 2~5대가 함께 온다.
  `1분`~`31분`이 관측되었다.
- **G-4.** **차량 식별자가 없다.** 별도의 "다음 차량" 이벤트도 없다.
  다음 차는 같은 본문의 두 번째 행이다. → 현재 차량 · 다음 차량 · 동일 차량은 모두 **추론**이다(제18원칙).
- **G-5.** `승차역 부근` · `승차정류장 부근` · `승착역 부근` 계열은
  22개 파일 전 필드에서 **0건**이다. → 제22원칙과 부록 E의 관측 등급 근거.
- **G-6.** 빠른 하차 · 빠른 환승 칸 정보는 **첫 승차 알림 본문에 이미 들어있다.**
- **G-7.** 하차와 환승 알림은 **같은 타임스탬프**로 온다.
  환승부터 첫 지하철 ETA까지의 실측 간격은 35초 · 38초 · 61초였다.
- **G-8.** `곧 도착` · `도착` · `1분` · `2분`은 **원본**이다.
  `곧 출발합니다` · `다음 열차는 …`은 **우리가 만든 문장**이며 원본에 0건이다.
- **G-9.** 혼잡도는 접근성 트리에만 있고 302 버스 행에는 없다.
- **G-10.** 같은 목적지에 안내 시작 알림이 한 주행 중 여러 번 등장한다.
